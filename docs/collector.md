# SHEFA Voice Commons: how to run it

A small, separate web app that lets friends, family and the community record made-up hospital
phone calls so SHEFA's speech recogniser can learn Bangla hospital talk. Design and reasons:
[`designs/shefa-voice-commons.md`](designs/shefa-voice-commons.md). Web API contract:
[`designs/collector-api.md`](designs/collector-api.md).

Everything runs on your own computer. Recordings are saved to `data/collector/` on your disk (never
in a cloud store), so there is no download-and-clear step, no storage cap and no foreign cloud
holding personal voice data. Contributors reach it through a free tunnel.

## One-time setup

```bash
uv run shefa collect init            # makes data/collector/, the database, the scripts, and the admin account
uv run shefa collect build-prompts   # speaks the agent's questions with the local Bangla voice (about 2 minutes)
uv run shefa collect staff add rina reviewer --name "Rina"   # one account per reviewer; "adjudicator" settles disagreements
```

`init` prints the admin username (`admin`) and a one-time password. You choose your own password at
first sign-in. `staff add` does the same for each reviewer (the one-time password expires after 72
hours). Forgotten password: `uv run shefa collect staff passwd <username>` (asks for a new one) or add
`--generate` for a new one-time password; `staff list` shows the accounts. You can also add people and
reset passwords from the staff page. Optional settings go in
`configs/collector.yaml` (ignored by git); every key is in `src/shefa/collector/config.py`.

Add a short welcome voice note from yourself (about 20 seconds; **m4a or mp3 so iPhones can play it**) as
`data/collector/voice_note.m4a` (`.mp3`, `.ogg` and `.webm` also work); the page plays it on the first screen. People answer a person.

## Running a collection day

```bash
uv run shefa collect serve
```

* Contributor page: `http://127.0.0.1:8100/` (put the tunnel on this port only).
* Staff page: `http://127.0.0.1:8101/` (your computer only: admin and review).

### Give it a public address for free

A Cloudflare quick tunnel needs no account (download the `cloudflared` binary from Cloudflare's
site, no installer or sudo needed):

```bash
./cloudflared tunnel --url http://127.0.0.1:8100
```

It prints an `https://<random>.trycloudflare.com` address. Quick tunnels have no uptime promise and
the address changes every time you restart it. If the address changing is a problem, use the static
page below. Never point a tunnel at port 8101.

### Make the link survive a power cut (recommended before a WhatsApp campaign)

```bash
uv run shefa collect shell ./shell --api https://<your-tunnel-address>
```

Upload the `shell/` folder to any free static host (GitHub Pages or Cloudflare Pages) and add that
page's address to `allowed_origins` in `configs/collector.yaml`. The page then always loads, keeps
recordings on each phone and uploads them when your computer and tunnel are back. Share the static
page's link, not the tunnel's. When the tunnel address changes, re-run the command and republish.

### Review sessions

Reviewers normally cannot reach your computer. For a review session:

```bash
uv run shefa collect serve --with-review
```

Reviewer and adjudicator accounts can then sign in on the public address at `/review/`. An admin
account cannot (it is answered exactly like a wrong password), and the admin routes are never on the public port. Stop the session when you are done.

## Making campaign links

Open the staff page, Campaigns, "New". A link like `https://.../?c=ab12cd` shows each person the
sender's name ("রাহুল পাঠিয়েছে") and tells you which group brought which recordings.

## Reviewing

Reviewers sign in with their username and password at the staff page. The page shows one clip at a time.
Convention (also shown on the page): write exactly what is said, numbers/dates/times as Bangla
words (typed digits are converted for you), phone numbers as digits, English words in Bangla
script, no punctuation, and flag anything unusable instead of guessing. Test-set clips are
transcribed blind by two people and settled by an adjudicator; a small share of the queue is
known-answer clips that measure each reviewer's accuracy.

## What a contributor does now (version 2)

Each round is a small phone call to one made-up clinic (শেফা ক্লিনিক: eight departments, each with an
অধ্যাপক, a সহযোগী অধ্যাপক and a সহকারী অধ্যাপক). The desk opens with salam and the clinic's name. The
contributor first taps who the patient is from a pair (ছেলে/মেয়ে, স্বামী/স্ত্রী, বাবা/মা...), each with a
name and age that fit. At a few points they choose what to say (pick a doctor, ask who is best, ask who
sits when, ask the fee, ask the address...), and the desk's next line follows that choice: asked for
advice, it recommends the most senior doctor. A call runs from about 5 to 16 turns and ends with a
goodbye. Scripts are generated by `src/shefa/collector/scripts.py`; `build-prompts` speaks every desk
line with the local voice (about 760 small files).

## Call topics, consent version 2 and sharing (since 2026-11-19)

* **Two topics.** Besides the hospital (শেফা ক্লিনিক) there are 120 calls to a made-up internet
  provider, SAFWA (সাফওয়া ব্রডব্যান্ড): no internet (customer care tries a router restart before sending a
  technician), slow speed (package change or technician), the bill and how to pay, a new connection,
  and shifting the line. Customer care asks for the customer ID or registered number first. The
  contributor picks a topic on the first screen ("যেকোনো" mixes both, about 60/40). Generated by
  `src/shefa/collector/scripts_isp.py`; the hospital calls did not change.
* **Online shop (since 2026-11-20).** 120 calls to SADAF (সাদাফ), a made-up online shop: where is my
  order, a late order (wait or cancel with a refund), wrong size or a damaged item (pickup, exchange
  or refund), a new order with cash on delivery and the delivery charge, and cancelling. Ids
  `v2-s###`, domain "shop", `src/shefa/collector/scripts_shop.py`; topic chip "অনলাইন শপ". SAFWA,
  SADAF, SHEFA and SAFAR are the founder's S-brands.
* **Phone-number drafts (since 2026-11-20).** The draft reader also understands run-together and
  misheard digits (জিরোয়ান, জিলো, সেক্স, "জিরো এন"), number pairs inside a number (একাশি), and repairs a
  dropped leading 0 or 1. A number that cannot be a Bangladeshi mobile, or a phone question with no
  number heard, marks the draft as unsure (confidence 0.4) so it comes first. On 68 reviewed numbers:
  29 -> 41 exact; 25 of the 27 still wrong are marked unsure. Swapping in the number the person was
  shown was tried and made it worse (people say other numbers), so it is not done.
* **Live calls with the real agent (since 2026-11-20).** "SHEFA-র সাথে কথা বলুন" lets a volunteer
  talk to the product's own booking agent (`collector/live.py`): each push-to-talk turn is an
  ordinary clip (slot `live`, no expected answer), transcribed with the shared Bangla Whisper,
  answered by `VoicePipeline.handle_text` with the LLM on **vLLM** (`localhost:8001`, start it with
  `uv run python -c "from shefa.cli import _ensure_vllm; _ensure_vllm()"`; it runs on its own and
  survives collector restarts), spoken with the product voice. The agent books only in a sandbox
  (`data/collector/live/agent-sandbox.db`, the collection's own made-up clinic, wiped at start);
  `data/shefa.db` is never opened. Edge cases handled: nothing heard or a low-confidence guess
  (below 0.6: Whisper invents sentences from noise) -> "আবার বলবেন?", three times -> end; agent
  slow or down -> polite end; agent ends the call (booked, emergency, hand-over) -> end; 2 calls at
  a time, one per phone, idle 3 min -> ended; 16 turns / 7 minutes max; retried turns get the same
  answer; turns never overlap; voice failure -> text only; offline -> never queued. Staff page tab
  "SHEFA কল" lists calls turn by turn (said / heard / answered / timings) with the volunteer's
  verdict. If vLLM is not running the button says SHEFA is off and scripted calls still work.
* **Departments said the real way (since 2026-11-20).** The clinic now has 23 departments (big Dhaka
  hospital list), 69 made-up doctors. The desk says the common form ("নিউরোলজি বিভাগে"); the caller's
  hint mixes forms: "নিউরোলজি বিভাগ", "Neurology Department", "স্নায়ুরোগ বিভাগ", "নিউরোলজিস্ট",
  "হাড়ের ডাক্তার". One table, `src/shefa/clinic/department_names.py`, serves the agent and the
  collection. Hospital card ids are now `v3-*`; cards that leave the bank are kept in
  `prompts/cards2-retired.json`, so clips recorded on them still resolve.
* **Wider voices (since 2026-11-20).** Free talk on half the calls; a "loudspeaker" place that
  counts toward the noisy goal; group goals for people aged 50+ and from outside Dhaka (25 each),
  shown after 10 clips and in the hand-over nudge.
* **Consent version 3** is one short general sentence that includes sharing/licensing; version 2
  people are not asked again.
* **Consent version 2** says recordings teach this project's Bangla voice assistants (SHEFA and
  customer care for internet or other services). People who agreed to version 1 see a short
  "সম্মতির কথা একটু বদলেছে" note and tick again; they stay the same person (same speaker id). Until
  they do, they only get hospital calls, and the server refuses an internet-provider clip from them.
* **Sharing or licensing is a separate, optional tick** ("(ঐচ্ছিক) অন্য প্রতিষ্ঠানের সাথে শেয়ার বা
  লাইসেন্স করাতেও রাজি"), asked for each person (also on a shared phone). Use
  `shefa collect export <folder> --shareable-only` for ANY set that leaves the project; every row in
  an export says `domain`, `dialect`, `consent` and `shareable`. `--domain hospital|isp` keeps one
  topic. **The consent wording is a draft: have a lawyer read it before selling or licensing.**
* **Dialect.** The optional profile asks which regional way of speaking the person uses at home;
  the admin stats count speakers by dialect, internet-provider minutes and people who agreed to sharing.

## Machine drafts for reviewers (since 2026-11-17)

`serve` drafts every clip in the background with SHEFA's own Bangla speech model (the GPU when it
is free, else the CPU), as soon as it arrives; existing clips are drafted the first time the server
starts. Each draft has a confidence (0 to 100%). The reviewer hears the clip, sees the draft
already typed in, and either taps "ঠিক আছে, পরেরটা" or corrects it. The queue serves the
**least sure drafts first**, with a red/amber/green note telling the reviewer how carefully to
listen, so attention goes where the machine is weakest. Admin > clips can also sort by confidence.
The founder chose drafts for every clip, test clips included; test clips still need two people who
agree. Turn it off with `auto_draft: false` in `configs/collector.yaml`; `collect draft` drafts by
hand.

## Two-person calls (guided, since 2026-11-17)

Both phones follow the same branching script as the single-person calls. The patient taps what to
say next from the options (a doctor, "who is best?", the fee, the address...) and says it in their
own words. The front desk then sees the professional line that answers it and says that in their own
words, with the rule on screen: answer only what the patient asks, take what the booking needs, do
not extend the call. The patient's choices move the call on (the server tracks where the call is),
so the desk never leads. Front-desk recordings are stored as front-desk speech and are left out of
the speech-recogniser training set by default (`export --include-desk` adds them).

## A real person as the front desk (voice packs)

Any staff member can open "ডেস্কের কণ্ঠ দিন" in the staff page, agree to the notice, and record the
desk's common lines (four openings first, then the questions, the doctor lists and the advice). You
listen to them under Admin > কণ্ঠ and switch that person's pack on. From then on a share of calls
(50% by default, adjustable there) use that person's voice for every line they recorded, and the
synthetic voice for the rest. A pack is used only for a call whose opening that person recorded.
Deleting the recordings, switching the pack off or deactivating the person stops it at once.
**Only staff voices are ever played to contributors.** Recordings from contributors are never played
to anyone but reviewers: their consent says "not published".

## Machine drafts, backups, measuring, exporting

```bash
uv run shefa collect draft                # draft transcripts for training-pool clips (uses the speech model)
uv run shefa collect backup /media/usb/collector   # verified copy to another disk; withdrawn clips never survive in it
uv run shefa collect score --hints        # baseline of the CURRENT model; --hints also tries booking-word hints (they hurt on synthetic audio, see docs/research/2026-11-15-*)
uv run shefa collect export ./trainset --phone-copies   # speaker-disjoint train/dev/test + 8 kHz phone-line copies
```

`score` and `export` print the go/no-go gate: about 100 speakers and 8 hours of reviewed audio
before a fine-tune is worth trying; below that, use the data as a test set. A fine-tuned model
ships only if slot-critical words (name, phone digits, day, time, yes/no) reach 90% on phone-line
audio and general Bangla does not get worse (`docs/fine-tuning-plan.md`).

## Privacy and safety checklist

* Contributors speak made-up details from the card; reviewers are told clips may still contain real
  ones and must not share them. Flag them and the clip is excluded.
* The audio never leaves your computer except through the tunnel's encrypted connection (Cloudflare
  passes the traffic). Reviewers hear audio only through short-lived signed links.
* Each person (also each person on a shared phone) has their own delete code, which removes only their recordings and leaves a tombstone so they cannot
  return from a backup. The consent text says a model that has already been trained cannot un-learn.
* Uploads pause by themselves when disk space is low or when you press Pause on the staff page.
* **Have a lawyer read Bangladesh's current personal-data rules** before a wide campaign (voice may
  count as sensitive data; sending data abroad has rules). This has not been verified here.
* Never publish the audio or a model trained on it without fresh consent (decision D6).

## Troubleshooting

* **Microphone blocked inside Facebook/Messenger:** the page detects it and shows "Chrome-এ খুলুন".
* **iPhone records nothing or in a strange format:** the page uses a WAV recorder with a
  MediaRecorder fallback; if a model of phone fails, ask the person to open it in Safari or Chrome.
  Test every phone type you can before a campaign.
* **Uploads say "paused":** disk free is below `min_free_disk_mb`, or you pressed Pause.
* **The link stopped working:** the tunnel restarted. Use the static page so only one place changes.

## Not built (on purpose)

A live in-browser two-person call (needs a relay server for mobile networks; the voice-message style
"call a friend" covers it), a public reviewer sign-up, a contributors wall with personal details,
automatic personal-detail detection, and any cloud storage adapter. The audio store has a small
interface (`LocalAudioStore`) so a cloud one can be added later.

## Version 2 switch-over (2026-11-16) and how to undo it

Switched with uploads paused; the backup taken just before is `data/collector/backups/pre-v2-20261116-2025` (243 clips,
database, audio and prompts). The new script bank is `data/collector/prompts/cards2.json` with its
desk audio in `prompts/q2/`; the first-version `cards.json` and `q/` stay for old queued clips.

To undo: pause uploads, `git checkout 206a402` (the last version-1 commit), restart only
`uv run shefa collect serve` (leave cloudflared running so the public address stays). The old code
ignores the new tables. It cannot sign anyone in with a password, so mint a version-1 token with that
old code: `uv run shefa collect staff founder admin`. Restore the database from the backup only while
uploads are still paused, or later withdrawals would come back.

Find the current public address of a running quick tunnel: `curl -s localhost:20241/quicktunnel`.

## Fixed link and start at power-on

The public link is Tailscale Funnel: `https://<machine>.<tailnet>.ts.net`, which stays the same
across reboots (the trycloudflare link changes every time). One-time setup:

1. Approve Funnel for the tailnet (the link `tailscale funnel 8100` prints), then
   `tailscale funnel --bg 8100`. tailscaled remembers it; nothing to rerun after a reboot.
   Only port 8100 is published; the staff site (8101) stays on this PC.
2. `bash deploy/autostart/install.sh` installs two user services: `shefa-vllm` (starts first and
   counts as up only when the model answers, so it gets its GPU share before Whisper loads) and
   `shefa-collector`. Both restart themselves after a crash.
3. `sudo loginctl enable-linger $USER` once, so they start at power-on, not only after login.

Day to day: `systemctl --user status shefa-collector`, `systemctl --user restart shefa-collector`
(pause the site first, as always). Logs stay in `data/collector/logs/serve.log` and `data/vllm.log`.
