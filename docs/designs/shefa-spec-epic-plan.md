# EPIC — SHEFA First-Clinic System: Safety-Net Wedge + Land-and-Expand

**Context**: Bangladeshi clinics can't answer the phone in fixed daily windows
(lunch, prayer, shift handover). The approved design (`docs/designs/shefa-safety-net-wedge.md`,
rev 1, 2026-09-25) scopes a door-opener: SHEFA covers the unmanned windows, captures
callback leads in Bangla, texts the desk, transfers emergencies. Same-week loop proof
precedes outreach (premise P2). **Scope note**: user expanded the epic beyond the
approved wedge — land-and-expand (booking depth, HMS paste-in, push-selling,
multi-branch/fleet) stays in scope as discover-then-build children; full dashboard
contract in scope; SIP trunk procurement is an implementer task. Demos the loop with
one simulated real call; outreach is the gate, not code (Q6).

**Current State**: local stack exists (`/api/v1/chat`, Twilio `/incoming`+`/media-stream`,
session manager, whisper_local/piper/qwen_local). The loop has never run end-to-end
with a real call. `configs/prompts/system.md` is dead (hardcoded `SYSTEM_PROMPT_TEMPLATE`
at `voice_pipeline.py:22`/`main.py:121`). No SQLite, no durable call log, no dashboard
view. Telephony config only has `twilio` (`settings.py:74-76`).

**Proposed Change**: One epic, 8 code children in design-doc order (steps 1-6 wedge,
then land-and-expand), sensible-DoD gates between phases.

**Children**:
1. **Media path** — B2BUA bridge (Asterisk ARI **+** FreeSWITCH ESL behind config-swapped
   interface; default the free/known path = Asterisk ARI, per Q9), replace Twilio-specific
   endpoints, wire `system.md`, trunk config + spend guard.
2. **Safety-Net conversation** — deterministic prompt pack, structured intents,
   emergency→transfer, no medical advice, degrade-to-transfer, disclosure + warm close.
3. **Lead sink + full dashboard** — additive SQLite calls table (Q10), desk notification,
   full D4 contract (two-number header, ring-2+ caveat, dispose filter, drill-down,
   audited-delete), D5 integrity.
4. **Test the real loop** — silence/noise/accents/code-switch/interruptions/failure,
   ≤2s median (Q11), calibration (E11), automated tests + VRAM (E12), E3/E6/E7/E9/E10.
5. **Runbook + dev docs** — X1/X2/X4/X6/X7/X8 (SIP-flavored).
6. **Demo deliverable** — 60s Bangla video of the proven loop (D1/D2).
7. **Booking depth + HMS paste-in** — booking slip in SQLite (not HMS-bound), availability
   lookup, discover-then-build HMS gate, push-selling outbound deferred.
8. **Multi-branch / fleet** — post-first-yes per-clinic deployment playbook, network play gated.

# CHILD 1 — Local telephony media path (SIP trunk → B2BUA → pipeline)

**Context**: The wedge's spine. A Bangladeshi SIP trunk terminates incoming calls into a
local Asterisk/FreeSWITCH; the B2BUA bridges the PSTN leg to the existing STT→LLM→TTS pipe
(`voice_pipeline.process_audio_stream`, which is transport-agnostic — a thin adapter). The
approved design rev 1 removes Twilio from the media path ("Twilio is a headache"). Spend is
hard-capped ~$10 trial week.

**Current State**: `twilio.py` handles `/incoming` + `/outbound-twiml` + `/outbound`;
media-stream WebSocket feeds `voice_pipeline.py:85` per `audio_queue`/`playback_queue`.
`system.md` unwired. No `sip` config section.

**Proposed Change**: Add `src/sefa/telephony/sip.py` with a `MediaBridge` interface and two
adapters (Asterisk ARI over WebSocket; FreeSWITCH ESL), selected by `telephony.sip.provider`;
bridge PSTN leg ↔ pipeline queues; wire `system.md` into `/api/v1/chat`; keep Twilio as
additive dev sink (Q5) via config flag.

**Implementation Details**:
- `MediaBridge` protocol → `AsteriskARIAdapter` + `FreeSWITCHESLAdapter`; both map slin/RTP →
  16kHz mono PCM (`pipeline.py` contract).
- `TelephonyConfig` gains `sip` block (`settings.py`), `provider: "twilio" | "asterisk" | "freeswitch"`.
- `main.py` mounts bridge router; Twilio router behind same config.
- system.md: load via `settings.llm.system_prompt_file`; regression test asserts the model
  name in `default.yaml` matches `qwen2.5:7b` (Q12).

**Acceptance Criteria** (re-scoped SIP-world E1/E2/E4/E8):
- [ ] Trunk-origin verification (registrar/peer auth) not `X-Twilio-Signature`; required-param
  validation → 4xx not 500; `UNIQUE(call_sid)` + INSERT OR IGNORE idempotency (E1).
- [ ] ANI per leg per carrier logged; hashed-ANI dedup + masked display; ANI caveat recorded (E2).
- [ ] Forward-on-no-answer verified on trunk (screen during procurement); forward type recorded (E4).
- [ ] Per-call costed guard + daily SIP usage poll from trunk operator (API/CDR) + 50%/90%
  alerts + hard stop; max-call-duration guard (E8); no costed path exceeds ~$10 without owner approval.
- [ ] One simulated real call completes greeting→capture→read-back over the SIP bridge.

**Tasks**: trunk plan + procurement (implementer, blocker: third-party web-drive + consent),
adapter modules, config, wiring, spend guard.

**Effort**: ~1 day (media path) + procurement waits. **Test Plan**: adapter unit tests w/
mock bridge; integration smoke via test-call page; latency timer. **Rollback**: `provider: "twilio"`
retains dev path.

# CHILD 2 — Safety-Net conversation

**Context**: Constrain the dialogue for trust. Deterministic prompts, structured intents
(appointment/result/billing/other), emergency→transfer, never medical advice,
degrade-to-transfer on failure. Disclosure from ring one.

**Current State**: `system.md` (17 lines) exists but is dead; the `/chat` + session manager
handle free-flow. **Proposed Change**: full prompt pack in `system.md` + intent router +
escalation keywords (`default.yaml` already has them at `escalation.emergency_keywords`).

**Acceptance Criteria**:
- [ ] Disclosure present in first greeting (Bangla-first, consent, "may be recorded").
- [ ] Intents parse to the enum; ambiguous → general (never guessed as booking).
- [ ] Emergency keywords (EN+BN) → warm transfer, no advice.
- [ ] D3 post-disclosure warm closing script + terminate; no dead air/hold/open prompt.
- [ ] Degrade: on STT/TTS/LLM failure → courtesy + DTMF capture / transfer.
- [ ] ≤2s median parse-to-reply, measured per turn.
